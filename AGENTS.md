# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Development Commands

- `npm install` — Install dependencies
- `npm start` — Web dev server (localhost:7474, HTTPS)
- `npm run mobile-start` — React Native Metro bundler
- `npm run android` / `npm run ios` — Run on device (Metro must be running first; iOS requires `cd ios && pod install` first)
- `npm run build` — Production web build
- `npm run lint` — ESLint + `tsc --noemit` (both must pass)
- `npm test` — Jest
- `npm run clean` — Clean React Native project
- `npm run gen:types` — Regenerate API client types from the `server` backend (see "API client" below)

## Cross-Platform Setup

React Native 0.77.2 + React Native Web. Single codebase ships to iOS, Android, and web. Webpack bundles for web; Metro for mobile.

Platform-specific files: `.tsx` (shared) → `.native.tsx` (mobile) → `.ios.tsx` / `.android.tsx` → `.web.tsx`. Webpack resolves `.web.*` first; Metro excludes `.web.*`.

Path aliases (mirrored in [tsconfig.json](tsconfig.json) and [babel.config.js](babel.config.js)): `@components`, `@screens`, `@config`, `@hooks`, `@utils`, `@assets`, `@types` → `src/<dir>`.

## API client (migration back-end)

The branch `new-backend-refactor` is mid-migration from a legacy REST API to the new backend (`../server`). Key conventions:

**Auto-generated, do not edit by hand:** [src/types/api/](src/types/api/) is regenerated by `npm run gen:types` (which shells out to `../server/scripts/gen-frontend-types.sh`). The script reads JSON Schemas from the backend, produces `<table>.{select,insert,update}.ts` and `apis.ts`, and copies `api_types/custom_endpoints.ts` from the backend verbatim. To add or change an endpoint wrapper, edit the backend source then regenerate — never edit the generated files directly.

**Calling the API:** import `api` from `@types`. It's a Proxy that throws "accessed before `initApi()` resolved" if used before bootstrap. Methods are typed CRUD (`api.<table>.read/list/create/update/delete`) merged with custom endpoints (`api.accounts.me`, `api.config.get`, `api.rates.current`, `api.transactions.byAddress`, …). See [src/types/client.ts](src/types/client.ts) for the proxy + `initApi` / `handleApiError` / `createWithFiles` helpers.

**Bootstrap chain (Root.tsx):** `useApiReady` → `useRuntimeConfigReady(isApiReady)` → render `<App />`. Both must resolve before the app mounts. `initRuntimeConfig` calls `api.config.get()` (so it depends on `initApi` having resolved) and caches the result; sync accessors (`getBitcoinNetwork`, `getBitcoinNetworkLib`, `getEnvironment`, `getCdnEndpoint`, …) are exposed from `@config`. See [src/config/runtimeConfig.ts](src/config/runtimeConfig.ts).

**snake_case is canonical.** Backend records use `snake_case` (`invoice_key`, `is_atm`, `deposit_address`, `hmac_secret`, …). The legacy API exposed `camelCase` aliases (`apiKey`, `isAtm`, `depositAddress`, …) which are still present on `AccountReadResponse` marked `@deprecated` for Node-RED compat — **do not consume them in front-end code**, always read the snake_case canonical field. SQLite int-bool columns (listed in `BOOL_COLUMNS` in [apis.ts](src/types/api/apis.ts), detected at codegen from `CHECK(col IN (0,1))` migrations) are coerced to `boolean` at the SDK boundary in both directions.

**Auth:** the backend doesn't set cookies in JSON mode — tokens are persisted via the `Storage` adapter passed to `initApi` (web → `localStorage`, mobile → `AsyncStorage`). `client.fetch` auto-refreshes on 401. Some endpoints accept dual auth (api-key OR JWT) — pass `{ apiKey }` to opt into header-based auth for that single call (e.g. `api.accounts.me({ apiKey })`).

## Root.tsx context provider chain

[Root.tsx](src/Root.tsx) wraps the app in a deeply nested set of providers. Order matters because hardware-wallet providers (`SBPTrezorContextProvider`, `SBPLedgerContextProvider`, `SBPBitboxContextProvider`) feed into the unified `SBPHardwareWalletContextProvider`. When adding new global state, place it inside `SBPThemeContextProvider` (so theming is available) and respect the existing top-down dependency order.

## Build-time env vars

Web: declared in [webpack.config.ts](webpack.config.ts) via `DefinePlugin`. Currently injects `NODE_ENV`, `COMMIT_REF`, `SENTRY_DSN`, `DASHBOARD_URL`. **Do not add new `process.env.*` vars without registering them here.** Mobile: `react-native-dotenv` with explicit `allowlist` in [babel.config.js](babel.config.js). Runtime config that depends on backend state (Bitcoin network, environment, CDN, version gating) goes through `/v1/config` and `runtimeConfig.ts`, not env vars.

## Bitcoin / Wallet specifics

- BIP84 derivation, p2wpkh default ([src/config/bitcoin.ts](src/config/bitcoin.ts)).
- Hardware wallets: Ledger, Trezor, Bitbox02, all behind their own context provider in [src/config/SBPHardwareWallet/](src/config/SBPHardwareWallet/).
- `getBitcoinNetworkLib()` returns `bitcoinjs-lib` `networks.bitcoin` for mainnet and `networks.testnet` for `signet` (bitcoinjs-lib has no signet entry; testnet params are address-compatible).
- Lightning, NFC/BoltCard payments, on-chain auto-withdraw, non-custodial wallet derivation are all coordinated through the API client + hardware wallet contexts.

## Notes

- Sentry + react-native-error-boundary wrap routes; SSL pinning, biometric auth, encrypted storage, and screen-recording prevention are configured in mobile-only modules.
- The branch `new-backend-refactor` has many in-progress files — pre-existing TS errors are common during the migration; verify your changes don't introduce *new* errors rather than expecting a clean `tsc --noemit`.
- **Ask when in doubt.** This codebase is mid-migration with several non-obvious conventions (snake_case vs camelCase aliases, auto-generated files, dual-auth endpoints, bootstrap ordering). If a requirement is ambiguous, a field's canonical name is unclear, or a refactor's scope is unclear, stop and ask before guessing — silent assumptions in this area tend to cascade.
